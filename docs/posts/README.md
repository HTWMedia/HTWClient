# 分发清单

目标不是「更多人看到」，是**搜这个问题的人能看到**。所以标题一律用问题句，不用产品名。

## 零、从哪里开始（2026-11-09 定）

**结论：先修漏斗末端和稳定承诺，再发内容，最后才谈拉新。** 依据都是可复核的事实：

| 事实 | 数据 |
| --- | --- |
| 技术内容这条路对我们有效 | `HTWMedia/JyDraft`（HDraft）92 star / 10 个 release，2026-11-07 仍在发 v1.8.0；对比本仓 2 star / 0 issue / 0 订阅 |
| 漏斗末端是断的 | JyDraft 4 个待处理 issue 里，2 个是 2026-02-25 的「群二维码失效了」「群没有了，可以重新发一下吗？想进群学习交流一下」，至今未回；它的 README「交流」段用的是一张会过期的二维码图片 |
| 「重构不稳定」有工程实证 | 本仓 11-06 `refactor` 下线剪同款、拆账号池，11-07 `feat!` 把草稿导出改成必须自备登录态 —— 4 天内两次破坏性变更；README 自己也注明教程录于 v0.5.0、之后三个面板改过版式 |
| 内容其实不缺 | `docs/articles/` 已有 8 篇成稿，`examples/pyjianying-draft/README.md` 有实跑输出，`HTWCore.Web/docs/2026-10-11-style-filter-protocol.md` 有十节协议取证 |

三步按依赖排，不要跳步。

### 第 0 步（先做，不涉及放量）：把门修好 + 立稳定契约

1. **群入口换成不会过期的形式**：置顶 issue / Discussions / 固定短链，别再用一张 7 天就失效的二维码图片；「交流」段同时给一条「提 Issue 也算参与」的低门槛路径 —— 这正是竞品作者在群里说的「不会写代码，提个 Issue 就是最大的帮助」的落点。
2. **回掉挂了 8 个多月的两个进群 issue**，并给「贴纸渲染不对」一个明确结论（哪怕是「已知限制，暂不支持」）。开源项目的活跃度首先体现在响应，不在发帖频率。
3. **对外贴一份稳定契约**：列清哪些不破坏（CLI 命令、`/api/v2/*` 信封与状态码语义、草稿形态、桌面端配对协议）；破坏性变更必须提前公告 + 给迁移步骤 + 保留旧版下载。本仓目前没有 `CHANGELOG.md`，README 的「v0.5.2 更新」是唯一版本公告位 —— 补一个能对外贴的兼容承诺，比再写十篇文章更能止住「跟着用会被坑」的印象。
4. 这一步**不动**「合规完成前不放量」那个开关：修入口、回 issue、发技术考据都不等于开闸推广，属于把漏斗修好。

### 第 1 步：用「剪映草稿解析」这类硬材料写第一篇公众号长文

竞品作者验证过的文章骨架：**痛点开场 → 一句话定义 → 能力拆解 → 适用场景与边界表 → 三行命令上手 → 前提与限制 → 结尾征集真实反馈**。标题不带产品名，靠问题句吃搜索长尾；文章会被第三方号自发转载，一次写作多次分发。

我们手里有他写不出来的素材（全部已有实跑证据，不需要新功能）：

- 官方 Web 草稿里滤镜的四个形态差异：位置、7 位短效果标识、`path`、独立滤镜轨；
- 「渲染成功 ≠ 有效果」：管道不报错也可能整段被云端静默跳过，必须按帧号抽帧做像素对照；
- 25 条精选滤镜逐条云渲染对照（25/25 生效）+ 26 段无滤镜噪声基线；
- 参数化调色的五个容器恒为空、接口无对应面板的否定取证；
- `examples/pyjianying-draft/README.md` 里可直接贴的命令与真实输出。

标题备选：**「草稿渲出来了，滤镜为什么没生效」**、**「剪映草稿里的滤镜，到底写在哪才有效」**。
⚠️ 必须避开「解密」「不装剪映」「绕过」「破解」这类词（11-06 整改口径）；JyDraft 的仓库描述仍含加解密字样，与本仓口径不一致，属待拍板项，**不要混用**。
落点给三层：在线体验 `htwmedia.dpdns.org` / 桌面端 release / 仓库；文末征集「一场真实使用场景」而不是求 star。

### 第 2 步：把群从通知群改成「稳定公告 + 场景收集」

每周一条固定格式：**本周没坏什么 / 修了什么 / 征集一个真实场景**。用 issue 模板承接反馈，公开说明破坏性变更的提前量。
衡量第 0 步是否见效，看 **群里有人回一个真实使用场景、issue 数从 0 变正**，不是看 star 数。

### 不要先做

- 不要在门修好之前投新内容 —— 流量没有落点；
- 不要先做 B 站单条短视频（要视频制作，且放量开关未拍板）；
- 不要先改 GitHub 仓库描述 / 话题（11-06 特意去掉搜索词以留合规缓冲，属口径决策）；
- 不要先加新面板（11-06 / 11-08 两轮诊断已判定「每个面板都是竞品第二名」是定位过宽所致）。

> **2026-11-06 调整**：原计划里的两篇稿——「不装剪映把草稿渲成片」和「剪映加密草稿怎么解」——已删除。
> 它们把「绕过剪映」写在了标题里，而这类表述正好是对方最有理由投诉的抓手（同类结构已有生效判决）。
> 草稿导出本身保留为进阶用法，但不作为对外宣传的第一卖点。

## 建议补的选题（按搜索价值排序）

这三类都能公开写、不带风险，而且都是真需求：

1. **「今天发什么」怎么用数据回答** —— 选题类。关键词「抖音选题」「对标账号 分析」，读者是日更创作者，正好是目标人群。
2. **爆款文案拆解怎么做成模板** —— 关键词「爆款标题 拆解」「小红书文案 结构」。可写成方法文，工具只做示例。
3. **四个平台一起发，坑在哪** —— 关键词「多平台发布 区别」「抖音 小红书 同步发」。比第 1 篇更工程向，转化最高。
4. **剪映草稿形态考据（公众号向，第 1 步首选）** —— 关键词「剪映草稿 结构」「滤镜 不生效」。
   这是竞品作者验证过最能吃长尾搜索的题材，且素材全在手里：协议文档十节 + 25 条逐条像素对照 +
   示例 README 的实跑输出。写法见上面第 1 步，标题用问题句，避开禁词。
