# 不装剪映，把草稿批量渲成片：这条链路我是怎么打通的

> 适合读者：手上有几十个剪映工程、但是一台机器一个人，导不完的人。
> 关键词：剪映草稿导出、批量渲染、无需安装剪映、云端成片

## 先说痛点

剪映的工程文件（`draft_content.json`）是明文协议，社区里生成草稿的开源项目不少——写好 JSON、丢进草稿目录、打开剪映就能看到。但**生成草稿只到一半**：最后那一步「导出成片」仍然要打开剪映、点导出、等渲染、再换下一个工程。

一天十条片子，这一步就能吃掉半天。而且它绑死一台机器：剪映必须在、显卡必须够、人必须在。

真正卡住的是最后一公里。

## 关键判断：渲染不一定要在本机

剪映自己的「云渲染 / 云备份」走的是它的服务端。也就是说，**草稿能不能出片，取决于你能不能把草稿和素材喂给那条云通道**，而不是取决于你本机装没装剪映。

顺着这个判断做下去，链路就变成三步：

1. 读草稿 → 解析出它引用了哪些素材（视频 / 音频 / 图片 / 字体）；
2. 把草稿 JSON + 素材打包上传，服务端传到云端并建渲染任务；
3. 轮询任务 → 拿到成片地址 → 回写到草稿同目录。

本机只负责打包上传和下载，几乎不烧资源。老笔记本、甚至一台没有剪映的 Linux 服务器都能跑。

## 三个必须处理的坑

**① 草稿是加密的。** 剪映 5.9 之后 `draft_content.json` 默认加密，直接读是乱码。判断依据是文件开头几个字节，不是靠扩展名。服务端解出来的才是真正可解析的 JSON。

**② 素材路径是绝对的。** 草稿里记的是 `C:\Users\xxx\...\clip.mp4` 这种绝对路径。换台机器、挪过文件夹，素材就全断。所以打包时必须**按草稿里的文件名重新对齐**，缺哪个要在提交前就报出来，而不是等渲染完发现画面是黑的。

**③ 曲库音乐渲染不了。** 草稿里用了剪映「曲库」的音乐（素材带 `music_id` / `effect_id`），云端会返回 `200403 create render task failed` —— 曲库音乐的授权绑在原账号上，渲染账号没权限解析。把那条音乐换成本地音频文件就好，实测同一草稿只去掉曲库音乐轨道，其余部分正常出片。

## 现在长什么样

一条命令，传目录就行（会自动打包，保留子目录结构）：

```bash
export HTW_API_KEY="your-key"
node htw-skills.mjs draft "C:\Users\me\AppData\Local\JianyingPro\User Data\Projects\com.lveditor.draft\我的草稿"
```

批量就套一层循环，退出码是给脚本用的：`0` 成功、`1` 渲染失败、`2` 参数错、`3` 没设 key、`4` 额度用完。失败不影响其他草稿。

草稿路径不用猜：剪映里右键草稿 →「打开草稿文件夹」，就是它。

## 取舍

- **要联网**。渲染在云端，断网就干不了。敏感素材自己评估。
- **排队**。免费档单并发，工作室档才有多路并发。急着出片的时候这是硬约束。
- **不是本地方案**。想要完全离线、本机渲染，这条链路不适用。
