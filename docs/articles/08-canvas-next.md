# AI 视频工作流的下一站：从"生成即结束"到可迭代画布

> 这一篇不是 bug 复盘，是产品判断。起因是行业里刚出现的一波"无限画布"形态，
> 我们拿它对照自己的产品，最后得出了一个**反直觉的结论：先别做画布**。

## 一波新形态的共同点

最近几家做创作工具的，不约而同把主界面换成了"无限画布 + 多轨道编辑器"的双核心：
一句话或者一份文档进来，先在画布上梳思路、成脚本，再调各种模型生成图片/视频/音频，
最后进多轨编辑器精修。卖点很直白——**减少跨工具反复导入导出**。

我扒了几家（包括一些开源实现）之后，发现"无限画布"这个形态有五条共性：

1. **节点化**：提示词 → 模型 → 产物，一个个节点，连线即流程，可以单独重跑某一步；
2. **非破坏性迭代**：保留创作轨迹和分支，而不是"生成一次，不满意就重来"；
3. **模板化**：搭好的工作流能存成模板，改提示词批量产出；
4. **工程持久化**：项目列表、版本、导出，资产随时回看；
5. **Agent 与画布互通**：选中某个节点直接对话，结果插回画布。

第 2 条是核心。它解决的是 AI 创作最痛的一点：**生成是一次性的，而创作是反复的**。

## 对照我们自己：缺的不是能力，是"工程"

我们的工作台有十个面板：选题、创作、短剧、洞察、剪辑、营销成片、发布、工具……
听起来很全，但拿上面五条一对照，暴露出两个断裂：

**断裂一：面板之间是手工搬运。** 选题面板算出今天该发什么，用户"去创作"的操作
本质是**把标题复制过去**。数据不跟着走，画像不跟着走。

**断裂二：创作链路是个黑盒。** 一次跑到底，中间产物看不见也改不了，
用户能做的只有"确认 / 重新生成 / 精修"三个按钮。
**这就是典型的"生成即结束"。**

有意思的是——我们把后端翻了一遍，发现**中间产物其实一直都在**：
脚本、调研、关键点、素材、配音、视觉、音乐、模板、合成，九类产物都存着，
而且**已经有节点级的操作端点**（重新生成某一步、精修某个产物、开关某个步骤、
替换素材、上传素材……）。

换句话说：**能力早就有了，缺的是把它们组织成一个"工程"的那层**。
我们不是缺功能，是缺一个能看见、能回看、能继续的容器。

## 为什么我们决定先不做真画布

真·无限画布很酷，但它是个重活：缩放平移、节点布局、连线序列化、
撤销重做、多人协作……**这些工作量跟"让用户能用上中间产物"这件事毫无关系**。

更大的风险是：**画布是个形态，价值来自里面的内容**。
如果工程层没做好，画布上放什么？放一堆一次性的生成结果，那只是把"生成即结束"
画得好看了一点。

所以我们把顺序倒过来了：

| 顺序 | 做什么 | 为什么先做它 |
| --- | --- | --- |
| ① | **工程/项目层**：把九类产物持久化成 project，可列表、可回看、可继续 | 杠杆最大、改动最小，且不依赖任何新 UI |
| ② | **卡片列表**式"降级画布"：先验证"能看见中间产物"到底有没有人用 | 用最低成本验证价值，别一上来做真画布 |
| ③ | 选题"去创作"直接建 project，别再复制标题 | 打通第一个断裂点 |
| ④ | 工作流存为模板 | 对标"模板化"这条共性 |
| ⑤ | 助手面板做成真能操作的 Agent | 对标"Agent 与画布互通" |

做完 ①②，如果数据显示很少有人回看中间产物，那真画布就不该做——**省下来的是几个月**。

## 一条我们刻意不抄的路

这波形态里还有个诱人的方向：**Skill 商店**（把成熟工作流沉淀成可复用能力给别人用）。
我们决定不抄，理由很实在：上一个这么做的生态（GPT Store），
**因为分成机制说不清楚而没能起来**。在分成规则明确之前，
先服务好自用场景，**生态是结果，不是起点**。

## 带走的判断方法

- **区分"形态"和"价值"**：画布是形态，"非破坏性迭代"是价值。
  先验证价值，再投入形态。
- **先盘点已有资产再谈新建**。我们以为缺"画布能力"，盘点后发现缺的是"容器"——
  这两者的工程量差一个数量级。**动手前先 grep 一遍自己有什么**，这一步几乎免费。
- **用最丑的实现验证需求**。卡片列表一点都不酷，但它能在两天内回答
  "用户到底要不要看中间产物"这个花两个月做画布才能回答的问题。
- 行业新形态出来时，抄它的**共性**（上面那五条），别抄它的**界面**。
