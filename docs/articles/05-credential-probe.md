# 凭据校验不能联网？那就找一个本地可判的信号

## 现象

后台有三张凭据配置页（三个不同的上游平台）。每张页都有个"当前状态"：
有效 / 失效 / 未配置。

其中一页长期显示**有效**，但对应能力一直在报"凭据失效"。
我们手动点"重新校验"，有时绿有时红，**同一个 Cookie，前后几分钟结果不一样**。

## 第一反应（错的）

一定是上游接口偶发抽风——我们先这么想，于是加了重试、加了超时、加了缓存。
全都没用，因为**根本问题不在网络抖动**。

## 定位

我们把那次校验的原始响应全打出来看，同一个 Cookie 连续三次请求，
返回分别是 **403**、**502**、**401**。

三种完全不同的状态码，来自同一个凭据、同一个端点、相隔几分钟。
这说明什么？说明这个校验端点**在我们的服务端网络环境下，根本无法稳定区分"有效"和"失效"**：
出口 IP 被风控了，返回的不是"你的凭据对不对"，而是"你这个人我信不信"。

顺手我们还排掉了另外两个候选端点：

- `/api/models`：**永远返回 200**，无论 Cookie 是不是垃圾——它测的是服务存活，不是凭据；
- `/api/v1/users/me`：已经 **404**，接口没了，请求永远失败。

也就是说，我们当时能想到的"联网校验"三条路，一条测错东西、一条已经死了、一条不可信。

## 判据：校验端点必须能稳定区分有效/失效

这件事之后我们定了条硬规则，写进项目约定：

> 一个端点要能当凭据校验用，必须满足：**在服务端网络环境下，拿一个已知有效凭据和一个已知
> 失效凭据分别请求，返回必须稳定地不一样**。做不到，就别用它。

注意三个限定词：**服务端网络**（不是你本机浏览器）、**已知有效/失效的对照样本**、
**稳定**（不是"大部分时候"）。

我们的踩坑恰恰是因为只在浏览器里验证过——浏览器里一切正常，服务端出口 IP 是另一回事。

## 修法：换成不需要联网就能判断的信号

这些凭据本质上都是 JWT。**JWT 的过期时间就在 payload 里，本地解析即可**：

```csharp
public static DateTime? GetTokenExpiry(string cookieValue)
{
    var jwt = ExtractToken(cookieValue);      // 从 Cookie 串里抠出 token=
    if (jwt == null) return null;
    var payload = Base64UrlDecode(jwt.Split('.')[1]);
    using var doc = JsonDocument.Parse(payload);
    return doc.RootElement.TryGetProperty("exp", out var e)
        ? DateTimeOffset.FromUnixTimeSeconds(e.GetInt64()).LocalDateTime
        : null;
}
```

判据就变成了：`exp > now` 即有效（再留一点提前量）。
**不依赖网络、不依赖上游心情、毫秒级返回**，而且和"用户实际能不能用"高度相关。

对于另一类平台（需要真实建会话才知道行不行），我们保留了联网探测，
但把它降级为"辅助信息"，主判据仍然是本地可判的。

## 顺带修的：缓存导致的"改了不生效"

还有个隐蔽问题：凭据配置在一个单例服务里被缓存了。
用户在后台更新了凭据，服务拿的还是旧的——**表现就是"我明明改好了，怎么还报错"**。

改动很小：服务不缓存凭据对象，每次调用都从 manager 重新取
（manager 内部是内存缓存，没有额外 IO，性能无损）。

```csharp
// 之前：构造函数注入后一直用 _config
// 之后：每次调用都取最新
var cfg = _credentialManager.Get();
```

## 怎么防止再犯

- **三处同步**：这类页面都是"Model 里判状态 + 控制器里 Check 动作 + 页面三态渲染"，
  改判据要三处一起改，漏一处就会出现"页面说有效、接口说失效"。
- 我们给"状态判定"单独写了测试，用**构造出来的时间戳**而不是真实时间，
  这样测试不会因为"跑测试的时候刚好过期"而随机失败。
- 新增凭据平台时，先问：**本地有没有可判信号？** 有就用本地的，没有再谈联网探测，
  并且联网探测必须给出"有效/失效对照样本"的验证记录。

## 带走的结论

- **"接口能通"不等于"接口能用来做判断"**。先问它能不能区分两种状态，再问它通不通。
- **浏览器里验证通过 ≠ 服务端里验证通过**。出口 IP、风控、地域策略都会让结果分化。
  校验逻辑一定要在**和线上一致的网络环境**里验。
- 当联网信号不可信时，**优先找本地可判的确定性信号**（JWT `exp`、签名结构、字段名存在性），
  它们通常还更快。
- 单例缓存配置类数据，等于给用户埋一个"改了不生效"的坑——**配置就该每次取最新**。
