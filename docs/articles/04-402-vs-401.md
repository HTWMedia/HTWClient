# 402 不是 401：把"额度用尽"和"没登录"分开之后

## 现象

我们的桌面端有十来个面板，每个都会调不同的 AI 能力。早期版本里，"用不了"这件事
在不同面板长得完全不一样：

- 创作面板弹「生成失败，请重试」；
- 字幕面板弹「未返回内容」；
- 发布面板干脆什么都不弹，就一直转圈。

而真实原因往往是同一个：**这个账号的免费额度用完了**。

用户看到的是"软件坏了"，实际是"该充值了"。更糟的是，客服收到的报障永远带着错误的方向。

## 第一反应（错的）

我们一开始的处理方式是"就近兜底"：哪个面板报错就在哪个面板加文案。
结果是同一种状态在代码里散落十几个分支，加一处漏一处，而且
**额度状态是账号级的，却被当成某个面板的局部错误**——
用户在 A 面板看到"额度用完"，切到 B 面板又能正常点下去，然后再次失败。

## 定位

关键的一步是把失败原因分清楚。我们枚举了所有"用不了"的可能：

| 情况 | 谁的问题 | 用户该做什么 |
| --- | --- | --- |
| 没填 / 填错 AuthKey | 认证 | 去设置里改 |
| 账号被禁用 | 授权 | 联系客服 |
| **免费额度用尽** | **计费** | **去充值** |
| 上游限流 | 临时 | 等一会儿 |
| 上游凭据失效 | 运维 | 我们后台处理 |

前两类是 401，第三类是 402，后两类是 503/500 那一挂。
**它们以前全被我们塞进了同一个 else 分支**。

## 修法

**第一步：后端给出真正不同的状态码。**

```csharp
// 鉴权失败 → 401，不解释
if (!IsAuthenticated(ctx)) return Unauthorized();

// 免费额度用尽 → 402，并带上充值入口
if (!quota.HasFreeQuota(account))
    return StatusCode(402, ApiResult.Fail("免费额度已用完", redirectUrl: "/Home/Recharge"));
```

402 在这里不是"炫技用冷门状态码"，而是**让客户端能用一个整数区分两类完全不同的处置动作**。

**第二步：前端只在归一化层拦一次，不当成各面板的局部错误。**

所有响应都会过同一个 `normalize()`，额度这件事在这一层统一处理：

```js
function normalize(res) {
  if (res.status === 402) fireQuotaExceeded(res.data);   // 账号级，横幅
  return { ok: res.ok, code: res.status, ... };
}

function onQuotaExceeded(fn) { _quotaHandler = typeof fn === "function" ? fn : null; }
```

`app.js` 注册一个横幅回调：任何面板撞到 402，顶部出现统一的账号级提示 + 「去充值」按钮。
**面板自己不再负责解释额度问题**——它们只需要照常显示自己那部分错误。

**第三步：失败的任务不扣额度。**

这一点容易被忽略：任务因为上游异常失败了，如果照样扣一次，
用户会觉得"我没拿到东西还被扣钱"，是体验上最伤的一种。
我们的规则是**只有真正产出结果才计数**，失败路径在 `Complete(success: false)` 分支里不计数。

## 顺带加的（和不该加的）

后端还有个防刷中间件：只对 POST 生效，只对**已经产出过 402 的路径**生效。
这个设计是刻意的——不要给所有请求都加一层判断。

不过它有个我明知道的粗糙点：**热点路径用了一个静态字典记录，且从不清理**。
也就是说一旦某个路径被误标记为"热点"，要等进程重启才恢复。
我们接受了这个代价，因为清理策略本身会引入新的复杂度和锁竞争，
而误标的概率很低。**写下来、让人知道，比假装它不存在要好。**

## 怎么防止再犯

- 归一化层加单测：402 必须触发回调且带上 `redirectUrl`；**非 402 不能触发**（防止有人写成 `status >= 400`）。
- 单测里还要覆盖"未注册回调"的情况：回调是 `null` 时不能抛异常。
  这是典型的"只有线上某个面板没注册时才会炸"的分支。
- 新增账号级状态时，**先问一句：这是面板级还是账号级？** 问对了，落点就对了。

## 带走的结论

- **状态码是给客户端做分支用的，不是给人看的**。语义分层做在状态码上，比做在错误文案上可靠得多。
- **账号级状态要有账号级的呈现**（全局横幅），别让它退化成十个面板各自的 toast。
- 拦截点**只留一个**。十处兜底 = 十处遗漏。
- **失败不计费**是底线，不是优化项。
- 明知道自己留了粗糙实现，就把它写进注释或文档——"已知缺陷"和"没想到的缺陷"代价完全不同。
